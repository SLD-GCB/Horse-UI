# HorseUI 弱网体验优化方案

> 目标场景：**线路质量差**的服务器（高延迟 / 丢包 / 抖动 / 被运营商 QoS 限速），要让代理体验明显更好。
> 状态：**P1（系统调优）+ P3（协议引导与订阅）已实施**（2026-10-17）。
> 说明：本次目标只针对「代理速度」，因此 **P2（面板自身开销）与 P4（实时速率显示）暂不做**——它们不影响代理吞吐。
> 适用版本：sing-box 1.14.3（字段语义按该版本官方文档核实）。

---

## 1. 结论与优先级

**优先级排序**：`P3 协议引导` ≈ `P1 系统层（UDP 缓冲）` > `P2 面板自身开销` > `P4 实时速率` >> `端口跳跃`

**四条核心认知（决定了优先级，也是最容易搞错的地方）：**

1. **Hysteria2 / TUIC 走 QUIC（用户态 UDP），BBR 对它们无效。**
   弱网下它们真正受益的是 **UDP 缓冲区类 sysctl**（`net.core.rmem_max` / `wmem_max` / `udp_mem`）。
   BBR 主要帮到的是 **TCP 系入站**（VLESS / VMess / Trojan）和 **sing-box 发起的出站连接**。
   → 界面上必须讲清，否则用户会以为「开了 BBR 就快了」。

2. **Brutal（丢包不减速）是弱网最大杠杆**，但必须按官方语义正确配置（见 P3-1/P3-2）。

3. 面板自身**每 3 秒无脑拉一次内核的全量连接列表**，连接数大时会实打实吃掉代理进程的 CPU。

4. 端口跳跃收益高，但要动 `PREROUTING` nat 规则，**有断网风险且跨发行版差异大**，放下一期。

## 2. 已核实的技术事实（sing-box 1.14.3）

> 来源：sing-box 官方文档（Inbound / Hysteria2、Shared / QUIC、Shared / Listen）。
> **铁律：本仓库用 `sing-box check` 校验配置，对未知字段严格报错——任何新字段名必须先实测再写进代码。**

### 2.1 Hysteria2 入站的拥塞控制语义（最关键）

| 服务端 `up_mbps`/`down_mbps` | `ignore_client_bandwidth` | 官方描述的效果 |
|---|---|---|
| 未设 | `true` | "Commands clients to use the **BBR CC** instead of Hysteria CC" |
| 已设 | `true` | "**Deny** clients to use the **BBR CC**" |
| 未设 | `false`（默认） | 客户端可自行指定（即客户端可用 Brutal / Hysteria CC） |

**推论（弱网选型）：**

| 模式 | 服务端 up/down | `ignore_client_bandwidth` | 效果 | 适用 |
|---|---|---|---|---|
| **A 服务端 Brutal** | **填**（= VPS 实际带宽） | 开 | 服务端按该速率硬推、**丢包不减速**；拒绝客户端用 BBR | **弱网最省事**，客户端无需配置 |
| **B 客户端 Brutal** | 留空 | **关** | 客户端自己填带宽启用 Brutal | 用户会配客户端 |
| **C 纯 BBR** | 留空 | 开 | 指示客户端改用 BBR | 公平 / 防滥用，但丢包会减速 |

> 注意：服务端带宽**填得过高会加剧丢包**，应填 VPS 的真实带宽。

### 2.2 Hysteria2 其他字段

- `bbr_profile`（1.14.0+）：`conservative` / `standard` / `aggressive`
- `brutal_debug`：Brutal CC 的调试日志
- `obfs`：`type` 支持 `salamander` / `gecko`（1.14.0+）；`gecko` 另有 `obfs.min_packet_size` / `obfs.max_packet_size`
- `masquerade`：字符串形式或对象形式（`type` + 各类型字段）
- `realm`（1.14.0+）：NAT 穿透中继

### 2.3 共享 QUIC 字段（Hysteria2 / TUIC 入站可用）

`initial_packet_size`、`disable_path_mtu_discovery`，以及继承自 HTTP2 的：
`idle_timeout`、`keep_alive_period`、`stream_receive_window`、`connection_receive_window`、`max_concurrent_streams`

### 2.4 共享 Listen 字段（可用于入站）

`tcp_fast_open`、`tcp_multi_path`、`udp_fragment`、`udp_timeout`、`disable_tcp_keep_alive`、`tcp_keep_alive`、`tcp_keep_alive_interval`、`reuse_addr`、`bind_interface`（1.12+）、`routing_mark`（仅 Linux）、`netns`（仅 Linux）

> **已废弃**（1.11 起，1.13 移除）：`sniff`、`sniff_override_destination`、`sniff_timeout`、`domain_strategy`、`udp_disable_domain_unmapping`。
> HorseUI 目前**没有**把 `sniff` 写进入站，而是写在 `route.rules: [{"action":"sniff"}]`，所以能通过 check。

### 2.5 `listen_port` 只接受单个整数

官方 Listen 文档中 `listen_port` 仅描述为 "Listen port"，**没有端口段/数组语法**。
→ **端口跳跃必须靠 OS 层 NAT** 把一段 UDP 端口 DNAT 到 sing-box 实际监听的那个单端口。

### 2.6 客户端侧字段名（易错）

- **Clash / Mihomo** 的 hysteria2 用的是 **`up` / `down`**（字符串，如 `"100 Mbps"`），**不是** `up_mbps/down_mbps`；端口段是 `ports`（短横线）+ `hop-interval`
- **sing-box 客户端** outbound 用 `up_mbps` / `down_mbps`（整数）；**留空即用 BBR**；端口段是 `server_ports`（冒号语法）+ `hop_interval`

### 3.2 关键数据结构

```go
type TuneItem struct {
    Key     string // 如 net.core.rmem_max
    Label   string // 中文说明
    Group   string // udp | tcp | conn | fs
    Current string
    Suggest string
    OK      bool   // 当前值是否已达标
    Safe    bool   // 是否纳入「一键应用」；false = 仅建议
    Risk    string // "" | low | mid
    Note    string // 为什么对弱网有帮助 / 风险
}

type TuneReport struct {
    Supported    bool       // Linux=true
    CanApply     bool       // root + /etc/sysctl.d 可写
    Applied      bool       // 99-horseui.conf 是否存在
    BBRAvailable bool
    MemMB        int64
    InContainer  bool
    Items        []TuneItem
    Warnings     []string
}

func Detect() TuneReport
func Apply() (TuneReport, error)  // 写 /etc/sysctl.d/99-horseui.conf + 备份原值
func Revert() (TuneReport, error) // 删文件 + 还原备份
```

### 3.3 参数集（`Safe=true` 才纳入一键应用；缓冲按内存自适应）

**UDP / QUIC（对 hysteria2 最关键）**

| 键 | 建议值 | 说明 |
|---|---|---|
| `net.core.rmem_max` / `wmem_max` | mem<1G→4M，<2G→8M，否则 16M | QUIC 用户态 socket 的收发缓冲上限 |
| `net.core.rmem_default` / `wmem_default` | 1M | 默认缓冲 |
| `net.ipv4.udp_rmem_min` / `udp_wmem_min` | 16384 | 每 socket 下限 |
| `net.ipv4.udp_mem` | 仅建议 | **不默认应用**（小内存/容器算错会伤全局） |

**TCP（帮 VLESS/VMess/Trojan 与出站连接）**

| 键 | 建议值 | 说明 |
|---|---|---|
| `net.ipv4.tcp_congestion_control` | `bbr` | **先检测可用性**，不可用则跳过该项 |
| `net.core.default_qdisc` | `fq` | BBR 标配，抑制 bufferbloat |
| `net.ipv4.tcp_slow_start_after_idle` | `0` | 空闲后不重置 cwnd |
| `net.ipv4.tcp_mtu_probing` | `1` | PMTU 黑洞探测（弱网/隧道尤其重要） |
| `net.ipv4.tcp_fastopen` | `3` | 省一次 RTT |
| `net.ipv4.tcp_tw_reuse` | `1` | 复用 TIME_WAIT，防出站端口耗尽 |
| `net.ipv4.tcp_fin_timeout` | `15` | 加速端口回收 |
| `net.ipv4.tcp_keepalive_time` | `600` | 更快回收死连接 |
| `net.ipv4.ip_local_port_range` | `10240 65000` | **mid 风险**（全局参数） |
| `net.ipv4.tcp_tw_recycle` | **禁止** | 4.12+ 已从内核移除 |

**连接与 fd**

`net.core.somaxconn=8192`、`net.ipv4.tcp_max_syn_backlog=8192`、`net.core.netdev_max_backlog=16384`、`fs.file-max=2097152`

### 3.4 必须处理的细节

1. **回滚要先备份**：首次 `Apply()` 把原值写 `<dataDir>/sysctl-backup.json`；只删配置文件无法还原内核运行值。
2. **BBR 可用性检测**：读 `/proc/sys/net/ipv4/tcp_available_congestion_control`，必要时 `modprobe tcp_bbr`。
3. **容器 / netns**：`net.*` 多为命名空间参数，用 `InContainer` 提示（`/.dockerenv` 或 `/proc/1/cgroup`）。
4. 改动收敛到**独立文件** `/etc/sysctl.d/99-horseui.conf`，**绝不** `sed` 污染 `/etc/sysctl.conf`。
5. 应用后提示「**需重启内核进程才生效**」（缓冲类参数只对新建 socket 生效）。
6. 调优**绝不进启动关键路径**，失败只影响本次调用，不影响面板启动。
7. install.sh 里该步骤必须容错（`|| true`），失败不能中断安装。

### 3.5 可选增强

`core/process/supervisor.go:79` 的 `cmd.Env = os.Environ()` 是注入 `GOGC` / `GOMEMLIMIT` 的天然位置（按内存算，如 `GOMEMLIMIT = 内存 * 70%`），可减少小内存机因 GC 抖动 / swap 导致的性能塌陷。建议给 `Supervisor` 加 `SetExtraEnv(map[string]string)`，由 `svc.NewCore` 读设置注入，避免耦合。

### 3.6 全局 BBR 滑块（2026-10-17 实施）

设置页「系统调优」卡片顶部放一个开关，直接切 `net.ipv4.tcp_congestion_control`：

- **开启**：`tcp_congestion_control=bbr` + `default_qdisc=fq`（BBR 的标配搭配）
- **关闭**：恢复 `cubic` + `fq_codel`（内核默认）
- 持久化：读改写 `/etc/sysctl.d/99-horseui.conf`，**保留文件里已有的其他参数**，不整份覆盖
- 接口：`POST /api/sys/bbr {enabled: true|false}`，返回最新体检报告，前端据此同步滑块
- 内核没有 bbr 模块时开关直接禁用；容器里 `/proc/sys` 只读时配置仍会写盘，`Detect()` 会把滑块拨回真实状态并提示「重启后生效」
- 只影响 TCP 系协议；QUIC 系走用户态拥塞控制，不受它影响

## 4. P2 面板自身开销（负载大时明显）

### 4.1 修改文件

`back-machine/internal/api/task.go`、`core/stats/clash.go`、`model/setting.go`、`store/seed.go`、`front-UI/src/views/Settings.vue`

### 4.2 内容

1. **修一个真 bug**：`task.go` 的 `collectOnce` 读的是原始设置值（实际恒为 `"auto"`），导致 **`EffectiveStatsMode()` 从未被调用**，无论配置如何都走 Clash 采集，summary 显示的 mode 与实际采集口径可能不一致。
   改为调用 `EffectiveStatsMode()`；注意 auto 模式首次调用可能触发内核能力探测（起子进程），需在 `startTasks` 前**预热一次**，别在请求路径里首次触发。

2. **自适应采样**：把「双 ticker 串行 select」改成「单 Timer + flush Ticker」。
   连续无增量时退避 `3s → 10s → 30s → 60s`，一旦发现增量立刻回到 `3s`。`collectOnce()` 改为返回 `bool`（本轮是否有增量）。

3. **`Connections()` 单次解析**：去掉 `[]json.RawMessage` + 逐条 `Unmarshal` + 整个 `metadata` map 的两遍解析，改嵌套 struct 一次解出所需字段；`Tracker` 内部 3 个临时 map 提升为字段并用 `clear()` 复用（单 goroutine 使用，需注释锁死该前提）。

4. **`client_stats` 定期裁剪**：`maintenanceLoop` 加每小时 ticker，删除 30 天前记录（当前只在该用户重置流量时删除，会无限膨胀）。

5. **采样间隔设置项**：`stats_interval`，取值 `auto | 3 | 10 | 30 | 60`，默认 `auto`；服务端做白名单校验，非法值回退 auto。

### 4.3 风险

- 口径修复后，若内核支持 V2Ray API，统计会从「按入站」切到「按用户」，需回归配额/禁用路径（`flushTraffic` 的 split 分支）。
- 退避期间统计精度下降（累计量不丢），可接受。

## 5. P3 弱网协议引导与订阅（收益最高的「正确用法」）

### 5.1 修改文件

`front-UI/src/views/Inbounds.vue`、`back-machine/internal/svc/sub.go`、`back-machine/internal/api/tools.go`（可选）、`front-UI/src/api/types.ts`

> **硬性前置**：所有新增 sing-box 字段必须先跑 `sing-box check` 实测通过，才写进 UI 已知键。

### 5.2 把 Hysteria2 拥塞控制的三种模式讲清楚

当前 `Inbounds.vue` 里「忽略客户端带宽」的 hint 只写了单一含义，容易误导。改成 §2.1 的**三分支说明**（模式 A / B / C），并明确标注「**弱网要 Brutal 效果，按 A 或 B 配，不要用 C**」。

### 5.3 「弱网优化」一键预置

- **hysteria2**：`obfs=salamander`（抗特征 / 抗 QoS）+ 提示填写 VPS 实际带宽（模式 A）+ 可选 `bbr_profile`
- **tuic**：`congestion_control=bbr` + `heartbeat`

### 5.4 补 QUIC 调优字段（走 `Extra` 透传）

`initial_packet_size`、`disable_path_mtu_discovery`、`idle_timeout`、`keep_alive_period`、`stream_receive_window`、`connection_receive_window`、`max_concurrent_streams`

实现要点：表单新增 `quic_*` 字段 → `buildExtra()` 映射为真实键名；`openEdit()` 回填并从 extra 中剔除；同步补进 `KNOWN_EXTRA_KEYS`，避免重复落到 `extra_raw`。全部「留空 = 内核默认」。

### 5.5 订阅下发（`svc/sub.go`）

- **Clash / Mihomo**：hysteria2 分支补 `up` / `down`（字符串 `"<n> Mbps"`）
- **sing-box 客户端**：hysteria2 outbound 补 `up_mbps` / `down_mbps`（`>0` 才写）
- hysteria2 URI（`hysteria2://`）**不加**带宽参数（非标准字段）

### 5.6 入站 Listen 性能字段的取舍

`tcp_fast_open` / `udp_timeout` 对 **QUIC 类入站几乎无收益**（QUIC 自管连接与超时），且与现有 `Extra` 平铺可能冲突。
→ 不做专门 UI（仅保留 `tcp_fast_open` 一个开关给 TCP 系入站），其余保持「高级 JSON」透传。

### 5.7 行为抹除（全协议多路复用）——2026-10-17 追加

**为什么**：高并发 TCP 真正被限速的原因不是带宽，而是**行为指纹**——代理把 N 个目标连接映射成 N 条到同一境外 IP:port 的 TCP，于是运营商侧看到「并发连接数 / 每秒建连数（CPS）/ 同一 SNI 的握手频率」远超任何真实应用。这类通用 QoS 不需要解密就能判定。

**做法**（设置项 `behavior_mask`，默认关）：
- 对**全部 TCP 系协议**（vless / vmess / trojan / shadowsocks）下发的客户端出站统一注入多路复用：
  - sing-box 客户端：`multiplex { enabled, protocol: "smux", max_streams, padding }`
  - Clash / Mihomo：`smux { enabled, protocol: "smux", padding }`（注意 Clash 侧 Shadowsocks 的 type 是 `ss` 而不是 `shadowsocks`）
- 可调：`behavior_mask_streams`（每连接并发流，默认 8）、`behavior_mask_padding`（填充帧长，默认开）。
- 实测：四种协议的出站注入后 `sing-box check` 全部通过。

**边界**：
- `hysteria2` / `tuic` 本来就在一条 QUIC 连接上复用流，不适用也无需适用。
- `vless://` 等分享链接没有标准写法承载多路复用，只对 Clash / sing-box 订阅生效。
- 代价是单条 TCP 的队头阻塞：浏览/社交收益大，大文件多线程下载可能反而变慢，所以做成开关而不是无条件开启。

### 5.8 连接数诊断（2026-10-17 实施）

`GET /api/stats/conns`：复用 Clash API 的 `/connections`，按 **来源 IP** 聚合「当前并发连接数 / 最近 60 秒新建连接数」，按经验阈值分级（≥200 注意、≥500 高危），并在仪表盘给出可执行建议（开行为抹除 / 改用 Hysteria2）。

- 只多解析三个字段（`metadata.sourceIP`、`metadata.host`（缺省回退 `destinationIP`）、`start`），不额外轮询，沿用 3 秒采样那套数据源。
- 当前是请求时现拉一次，仪表盘 10 秒刷新。
- 局限：同一 NAT 出口下的多人会叠加；内核不返回 `start` 时「近 1 分钟新建」不可用（接口用 `has_start` 标记）。
- 阈值只是「明显偏高」的经验判断，不同运营商策略差异很大。

### 5.9 UDP 特征抹除（2026-10-17 实施）

UDP 侧 sing-box 唯一能抹特征的手段是 **Hysteria2 的 `obfs`**（salamander / gecko）：它把 QUIC 报文整体打乱，DPI 既看不到 QUIC 结构，也拿不到包长分布。

落地为 `POST /api/sys/mask-udp`：给**所有未配置混淆的 Hysteria2 入站**自动生成混淆密码并立即 `apply`。

- 必须由用户显式触发：会改变服务端配置，**旧订阅必须重新导入**，否则连不上。
- **TUIC 没有等价字段**（sing-box 未提供 obfs），抹不掉；接口会返回 TUIC 入站数量，UI 里明确说明「对 UDP 敏感就改用 Hysteria2」。
- 出站侧（订阅里的客户端配置）本来就会把 `obfs` 带下去，所以抹除动作只需落在入站配置上。

## 6. P4 实时速率显示（让用户看见效果）

- `core/stats/clash.go` 新增 `WatchTraffic(ctx, onSample func(up, down int64)) error`：连 Clash API 的 **WebSocket `/traffic`**，**每秒只推 up/down 两个数字**，开销极小
- 复用已有依赖：`go.mod` 已直接依赖 `golang.org/x/net`，优先用 `golang.org/x/net/websocket`，避免新增模块

## 7. 下一期：端口跳跃（本期不做）

**最小可行实现**（仅供后续参考）：

1. 模型（仅 hysteria2 有意义）：`PortRange string`（如 `"20000-50000"`）、`HopInterval int`（秒）
2. sing-box 入站**不变**：`listen_port` 仍监听单端口（§2.5 约束）
3. OS 层 NAT：`iptables -t nat -A PREROUTING -p udp --dport <from>:<to> -j REDIRECT --to-ports <target>`（IPv6 用 `ip6tables`；nft 用 `redirect to :<target>`）
4. 持久化：NAT 规则重启即失，需在 `App.Run()` 里按 DB 重新下发
5. 订阅输出：Clash `ports: "20000-50000"` + `hop-interval`；sing-box `server_ports: ["20000:50000"]` + `hop_interval`

**为什么缓做**：动 `PREROUTING` 有断网风险；nft / iptables / legacy 后端差异大；firewalld / ufw 会冲掉自建规则；云安全组仍需单独放行整段 UDP；容器环境下可能根本没有 NAT 控制权；Windows 完全不支持。
**收益场景窄**（只在「运营商按单个 UDP 端口限速」时成立），建议 P1–P3 稳定后作为 **opt-in** 功能上，且必须 comment 标记 + 幂等 + 绝不随安装自动开启。

## 9. 通用约束

- 只用 `back-machine/`、`core/`、`front-UI/`、`service/` 四个目录，不新建顶层目录
- 平台相关代码一律用 build tag 拆分，**Windows 必须能编译**

- 延续既有原则：**默认安全、失败不锁死**（系统调优不在启动路径、失败不影响面板）
- 任何新 sing-box 字段：**先实测字段名，再写代码**
