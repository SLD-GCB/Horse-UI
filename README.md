# Horse-UI

_**線路與線路之間是沒有任何的差別的，沒有所謂的根本性差別，只有開源面板的開發者是否想優化鏈接速度的取舍問題。**_

一个自建的 **sing-box 单机代理面板**：在浏览器或 HorseBox 客户端里管理协议入站、用户、出站、证书、订阅与内核。

面板与 sing-box 跑在同一台机器上，sing-box 作为受管子进程运行，前端资源内嵌在单一二进制里，服务器不需要安装 Go / Node。

> **安装方法以发布包（Linux zip）里的 `README-install.txt` 为准**，那份文档和当次发布的二进制是配套的。
>
> 客户端请使用配套的 [HorseBox](https://github.com/SLD-GCB/HorseBox)：面板是自签 HTTPS，HorseBox 会按证书指纹校验，并在首次登录时提供临时加密连接。
>
> 为避免节点混乱，**一个用户只能绑定同一类节点**（同一个用户下面不会混装多种协议）。

天马协议&快马协议的配置方法：https://github.com/SLD-GCB/Skyhorse/blob/main/tianma/PANEL-CONFIG-GUIDE.md

## 功能

**协议与传输**

- VLESS（含 Reality）、VMess、Trojan、Shadowsocks（含 2022）、TUIC、Hysteria2、HTTP
- 传输层支持 TCP / WebSocket / gRPC / HTTPUpgrade / HTTP/2
- 入站/出站可视化配置，端口池自动分配，节点测速，批量新建与批量操作

**用户与订阅**

- 用户 UUID / 密码自动生成，一个用户可绑定多个入站（多节点）
- 流量配额、到期时间、订阅令牌可独立重置；超配额 / 过期 / 停用后订阅直接返回 403
- 订阅分发：通用（base64）、Clash(Mihomo)、sing-box 三种格式，各带二维码
- 订阅响应只下发配置，不附带流量头；客户端展示的额度由客户端本地记录（见「与 HorseBox 配合」）

**出站与路由**

- 11 种出站类型（含 WireGuard、链式转发），可视化路由规则，广告过滤

**证书**

- ACME 自动签发（Cloudflare / 阿里云 / DNSPod / HTTP-01）与自签证书
- 自动续签、HTTPS 热加载；证书表为空时启动自动生成自签证书
- 面板证书 SHA-256 指纹可直接复制，供客户端做固定校验

**IP 养护**

- 检测出口 IP、Google 区域与是否送中（YouTube Premium / Music 的 `GL` / `contentRegion`）
- 查询 `ipapi.is` 信誉分，检测历史和纠偏历史分开记录
- 检测周期：手动 / 20 分钟 / 每小时 / 6 小时 / 12 小时 / 每天 / 每周
- 纠偏：手动 / 自动；只有检测到 `CN` 才执行，不限制次数
- 固定人格（UA / 语言 / 平台）+ 持久化 Cookie，跨轮、跨天保持同一身份
- 每个目标区域带本地关键词、搜索语言、News 语言和 Maps 城市坐标
- 短周期自动减动作（20 分钟 1 个、1 小时 2 个、6 小时以上 3–4 个），并加入时间抖动和随机跳过
- HorseBox 专用 API 令牌，只作用于 `/api/ip-care/*`；令牌 AES-GCM 加密落盘

**玄武防火墙**

- 独立 nftables 表 `inet horseui_fw`，入站默认拒绝，只放行登记端口
- 启动时自动导入存量监听端口；节点端口和端口段随入站自动同步，删除节点自动回收
- 手动开放 / 关闭、端口保护（只观察不自动关）、IPv4/IPv6 黑名单
- 动态容量按协议 + 端口统计 TCP 连接和 UDP 流，初始容量 UDP 256、TCP 8，随后按资源和基线调整
- 超限连续 3 个采样后只关受影响的端口，5 分钟后尝试自动恢复；22 和面板端口始终保护
- 异常 IP 聚合和攻击事件记录，面板人工确认后永久封禁/解封
- `horseui-fwd` 独立数据面，规则表被外部删除后自动重建
- App 只读接口：防火墙状态、动态容量、端口、异常 IP、攻击事件、CPU/内存/硬盘

**内核**

- 一键安装 / 更新 / 启停，配置先校验再应用，日志查看

**安全**

- 面板 HTTPS 默认开启；除 Shadowsocks 外**所有协议强制 TLS 或 Reality**
- Bcrypt + JWT（改密即时吊销旧令牌）、登录限流与账号锁定
- CORS 白名单、面板 IP 白名单、审计日志、请求体上限

**弱网优化**

- 系统内核参数一键调优（UDP 缓冲 / BBR，可回滚）与全局 BBR 开关
- Hysteria2 拥塞控制三种模式引导、QUIC 调优字段、TCP Fast Open
- 天马 BBR / Brutal 可选，快马上行/下行限速，天马/快马流并发上限
- 行为抹除（全协议多路复用）、UDP 特征抹除、连接数诊断

**运维**

- 类 s-ui 的终端数字菜单：启动 / 停止 / 状态 / 查看改密 / 内核 / 日志 / 更新 / 卸载 / 系统调优
- 仪表盘显示 CPU 使用率、系统内存、磁盘占用和面板自身内存
- 单文件二进制，前端已内嵌

## 协议支持

| 协议 | 加密 | 传输 | 备注 |
|---|---|---|---|
| VLESS | TLS / Reality | TCP / WS / gRPC / HTTPUpgrade / HTTP | 支持 `xtls-rprx-vision` |
| VMess | TLS | 同上 | 支持 `alterId` |
| Trojan | TLS / Reality | 同上 | |
| Shadowsocks | 协议自带 | TCP | 支持 2022 系列，无需 TLS |
| TUIC | QUIC + TLS | — | 可选 0-RTT、心跳、拥塞控制 |
| Hysteria2 | QUIC + TLS | — | 混淆（salamander / gecko）、带宽、Brutal |
| HTTP | TLS | — | HTTP 代理 |
| SkyHorse（天马） | QUIC v1 + TLS 1.3 | 原生 QUIC 多流 / DATAGRAM | 第四代，BBR/Brutal，流并发上限 |
| FastHorse（快马） | TLS 1.3 | TCP + H2 CONNECT | 第二代，单连接多流，上下行限速 |

## 天马第四代 / 快马第二代

面板已经适配两代自研协议，字段可直接配置、随订阅下发。

**天马（SkyHorse）第四代**

- 移除第三代叠加的 smux，恢复 QUIC 原生多流，避免双层复用拖慢单流；
- `max_streams_per_connection` 由客户端流信号量强制，不再只是透传；
- 拥塞控制可选：`standard` / `conservative` / `aggressive`，或留空走 Brutal；
- Brutal 使用 `up_mbps` / `down_mbps`，BBR 忽略这两个值；
- 端口轮换默认关闭，只有显式开启且端口数大于 1 才执行；
- TUN 自动排除节点服务器 IP，避免代理流量被 TUN 抓回。

**快马（FastHorse）第二代**

- 从连接池改为单条 H2 连接 + 原生多流；
- `max_streams_per_connection` 客户端信号量、服务端 H2 并发流同时限制；
- `up_mbps` 客户端上行限速，`down_mbps` 服务端下行限速；
- 端口轮换默认关闭，端口段为空或只有一个端口时不轮换；
- 移除 `connections` / `target_mbps`，不再维护已无意义的连接池字段。

**面板对应字段**

```
天马入站/出站：端口段、端口轮换、启用端口跳跃、单连接流上限、
                上行/下行、拥塞控制、BBR/Brutal
快马入站/出站：端口段、端口轮换、启用端口跳跃、单连接流上限、
                上行/下行
```

## 快速开始

### 方式一：安装包（Linux）

解压后执行：

```bash
sudo bash service/install.sh
```

脚本会安装面板二进制、随包的 sing-box 内核与 systemd 服务，并做一次系统调优
（可用 `HORSEUI_TUNE=0` 跳过）。

默认监听 `0.0.0.0:8080`，面板 HTTPS 默认开启（自签证书），管理员账号 `admin`。
初始密码随机生成、只在首次启动时打印一次：

```bash
journalctl -u horseui --no-pager | grep -i 密码
```

如果检测到弱口令，启动时会**自动重置为随机密码**并打印新的密码（不会把面板锁死）。

### 方式二：Windows

双击 `horseui.exe` 进入终端管理菜单，选「启动」即可。首次启动同样会打印面板地址和管理员密码。

### 方式三：源码构建

```bash
# 1. 前端（产物写入 back-machine/internal/webui/dist，供 go:embed 使用）
cd front-UI
npm install
npm run build
cd ..

# 2. 后端
go build -trimpath -ldflags "-s -w" -o horseui ./back-machine

# 3. 运行（-run 跳过终端菜单，直接启动面板）
./horseui -run -data ./data
```

> 必须先构建前端再 `go build`，否则内嵌的是占位页。

## 首次登录

面板是自签 HTTPS，浏览器第一次打开会提示「不安全」。这时有两条路。

### 推荐：用 HorseBox 客户端登录（不经过浏览器）

1. 打开 HorseBox →「面板」→「首次登录」
2. 填 `https://服务器IP:端口`，点「临时连接」
3. 这条连接仍然是 TLS 加密的，只是第一次不校验证书；页面底部会有橙色横幅提示
4. 用终端打印的管理员密码登录
5. 建好入站和用户，复制订阅地址
6. 到面板「设置 → 客户端证书指纹」点「复制」
7. 回到 HorseBox「订阅」添加订阅：填订阅地址 + 指纹

从这以后，客户端每次 TLS 握手都会比对指纹，证书被替换会直接断开。

### 浏览器登录

直接打开 `https://IP:端口`，在证书警告页选择继续，然后用管理员密码登录。
浏览器不会做指纹固定，适合临时排障，不建议长期使用。

## 与 HorseBox 配合

HorseBox 是配套的双端客户端（Windows / Android），除代理之外还内置了下面这些能力，和面板是同一套证书与账号体系：

- **内嵌面板**：客户端里直接打开面板，走严格证书指纹校验；首次登录提供一次性临时加密连接
- **面板密码本**：在客户端里保存面板账号，登录页右上角一键填入；记录按面板去重，密码本地加密存储
- **SSH 终端**：「配置」页填 IP / 用户名 / 密码即可登录服务器，带 SFTP 文件传输和本地端口转发（`ssh -L`）
- **订阅用量条**：订阅卡片显示「已用 / 总额」。总额手填，已用是客户端本地累计（只算这台设备），面板侧仍然以数据库里的配额为准
- **IP 养护**：添加面板地址、证书指纹和专用令牌后生成卡片；点卡片立即检测，送中时按设置手动或自动纠偏；结果只在 App 内提示，不发系统通知
- **防火墙监控**：只读查看防火墙状态、动态容量、端口、异常 IP、攻击事件，以及服务器 CPU/内存/硬盘

面板这边不需要为客户端做任何额外配置：客户端只是消费者，账号、配额、到期、订阅令牌全部在面板里管理。

## 建节点与订阅

1. **入站**：新建入站，选择协议和端口。除 Shadowsocks 外，TLS/Reality 是强制项；自签证书可以直接选面板已有的那张。
2. **用户**：新建用户，UUID/密码自动生成；一个用户只绑定同一类节点，避免节点列表混装不同协议。
3. **订阅**：在用户详情里复制订阅地址，三种格式：

```
https://面板地址/sub/<令牌>                    # 通用（base64 链接列表）
https://面板地址/sub/<令牌>?target=clash       # Clash / Mihomo
https://面板地址/sub/<令牌>?target=singbox     # sing-box
```

订阅令牌可单独重置；禁用用户或配额/到期后会返回 403。

## IP 养护怎么用

1. 面板「IP 养护」里设置目标区域、检测周期和纠偏模式（手动/自动）；
2. 生成 IP 养护令牌，复制面板地址、证书指纹和令牌到 HorseBox；
3. HorseBox「设置 → IP 养护」添加服务器；点卡片进入详情页，在详情页里检测、纠偏、看历史和设置；
4. 详情页显示出口 IP、Google 区域、目标区域、送中状态、信誉分、最近检测/纠偏/错误、当前设置、检测历史和纠偏历史；
5. 送中时：
   - 手动模式：详情页点「检测并纠偏」或「直接纠偏」，也可在面板里操作；
   - 自动模式：面板按周期执行，App 只显示状态和进度；
6. 检测历史和纠偏历史分开记录，可在面板和 App 详情页对比。

令牌只作用于 `/api/ip-care/*`，不能登录面板。HorseBox 10.46 起不再发「IP 送中/纠偏完成」系统通知，只在 App 内提示；VPN 前台通知不受影响。HorseBox 10.50 起卡片点击改为进入完整详情页。

## 玄武防火墙怎么用

完整 Linux 包会安装：

```
horseui.service      面板
horseui-fwd.service  防火墙数据面
sing-box             随包内核
nftables             缺失时自动安装
```

面板操作顺序：

1. 「玄武防火墙 → 导入存量端口」，确认 22、面板端口、节点端口都在列表；
2. 先不要开自动关端口，点「应用」，确认业务正常；
3. 点「启用」；启用后入站默认拒绝，只放行登记端口；
4. 常开的端口点「锁定开放」；不想让它被自动关，也可以只加锁定，不改变开放状态；
5. 观察动态容量正常后，再开「自动关端口」；
6. 攻击时：
   - 动态容量连续 3 个采样超限，只关受影响的端口；
   - 临时关闭的端口进入 5 分钟冷却，连接回落后自动恢复；
   - 永久关闭的端口会锁定在关闭状态，不自动恢复；
   - 22 和面板端口默认硬保护，不会自动关，避免把自己锁在门外；
7. 「攻击日志」看异常 IP 和攻击事件；
8. 「黑名单 → 异常 IP」里人工确认后永久封禁，已封可解封。

端口状态和按钮语义：

```
开放 + 不锁定  → 按动态容量自动开闭
开放 + 锁定    → 永久开启，常开
临时关闭       → 关闭 + 解除锁定，5 分钟后尝试恢复
永久关闭       → 关闭 + 锁定，不自动恢复
```

动态容量表会显示：

```
关闭时间
自动恢复倒计时
永久开启 / 永久关闭 / 临时关闭
```

注意：

- 防火墙默认关闭，第一次启用前必须确认存量端口已导入，否则可能断开业务；
- 端口「关闭」是保留规则但拒绝流量，不是删除；
- 永久封禁只针对确认来源，UDP 源 IP 可能伪造，不要看到一次就永封；
- 规则表被其他工具删除时，`horseui-fwd` 会自动重建；
- 关闭防火墙或关闭自动保护时，旧容量快照会被清除，重新启用后由 fwd 重建；
- 面板和 App 的防火墙监控都是只读展示，管理动作仍在面板。

HorseBox 的「设置 → 防火墙监控」可以看到：

```
服务器 CPU / 内存 / 硬盘
防火墙状态
动态容量（TCP/UDP）
关闭时间 / 自动恢复倒计时
永久开启 / 永久关闭 / 临时关闭
异常 IP
攻击事件
端口规则
运行日志
```

它使用 IP 养护令牌，只读，不能开关端口或封禁 IP。HorseBox 10.50 起动态容量详情页支持 `closed_at`、`recover_at`、`locked` 字段。

## 证书与指纹

- 证书表为空时，首次启动自动生成一张自签证书（SAN = 本机各网卡 IP + `localhost` + `127.0.0.1` + 主机名），有效期 10 年
- 「设置 → 客户端证书指纹」可以查看/复制 SHA-256，默认隐藏
- 续签或换证书后指纹会变，客户端需要重新复制
- 如果面板前面有反向代理终止 TLS，指纹页会提示：那里显示的是面板内部证书，客户端看到的证书以代理为准
- ACME 证书可以正常用于浏览器和公网域名；HorseBox 的指纹固定只对自签证书生效

## 安全建议

- 改掉默认端口，尽量不要长期把面板端口直接暴露在公网；需要时配合防火墙只放行自己的 IP
- 「设置 → 面板 IP 白名单」可以限制来源，默认关闭
- IP 养护令牌只作用于 `/api/ip-care/*`，不能登录面板；数据库里是 AES-GCM 密文，密钥在 `ipcare_token.key`
- 管理员密码只存在终端输出里，登录后可以在面板里改；改密会让所有旧 token 立即失效
- 面板 HTTPS 证书加载失败时会回落明文并打印告警，保证不会把自己锁在门外；确认证书正常后尽快恢复
- 不要把 `data/` 目录提交到仓库或分享出去

## 数据与备份

运行数据默认在 `-data` 指定的目录（Linux 安装包为 `/etc/horseui`）：

- `horseui.db`：SQLite，用户、入站、订阅令牌、设置
- `certs/`：证书和私钥
- `config.json`：生成的 sing-box 配置
- `logs/`、`bin/`（内核）
- `ipcare_cookies.json`：IP 养护的 Google 匿名会话 Cookie（0600）
- `ipcare_token.key`：IP 养护令牌加密密钥（0600），备份时需要一并保留

备份只需要停面板后整目录复制；恢复时放回同一路径再启动。

## 开发

- Go ≥ 1.27，Node ≥ 18
- 前端构建产物目录由 `front-UI/vite.config.ts` 的 `build.outDir` 指向 `back-machine/internal/webui/dist`
- 新增 sing-box 配置字段时，先用 `sing-box check` 实测再写进代码（内核对未知字段严格报错）
- 面板证书热加载的钩子在 `obtainCert` / `generateSelfSigned` 的 `db.Save` 之后，改证书流程时别绕开

## 常见问题

**启动后浏览器打不开面板**

看启动日志里的实际监听地址；端口被占用时面板会回退到启动参数里的地址，不会启动失败。

**忘了管理员密码**

终端菜单里有「重置密码」。

**客户端提示证书指纹不匹配**

面板换过证书。到「设置 → 客户端证书指纹」重新复制，更新到客户端订阅里。

**IP 养护一直显示 CN**

先确认出口 IP 的注册地和 ASN；机房 IP 或注册地在 CN/HK 时，行为纠偏可能无效。可以先用 1 小时周期观察 3–7 天，仍无变化就换 IP，不要长期用 20 分钟高频。

**到了周期但 IP 养护没执行**

新版本有随机抖动和跳过：20 分钟模式实际会在 16–24 分钟执行，约 20% 概率跳过一轮。超过 40 分钟仍没有记录，再查 `next_check_at` 和面板日志。

**IP 养护令牌和面板密码是一回事吗**

不是。IP 养护令牌只能调用 `/api/ip-care/*`，不能登录面板；面板登录仍然需要管理员密码和 2FA。

**订阅返回 403 / 404**

403：用户被禁用、过期、超出配额，或 User-Agent 被白名单拦了。404：令牌不对或该用户没有可用入站。

**防火墙启用后节点连不上**

先看「玄武防火墙 → 端口」里节点端口和端口段是否已导入，`service_udp` / `service_tcp` 是否包含该端口。刚启用时不要同时开自动关端口，先确认业务正常再加入保护。

**攻击日志是空的**

攻击日志只在防火墙已启用、自动关端口已开启、连接超过动态容量时记录；保护端口会记录观察事件但不自动关。依赖 conntrack，没有 conntrack 时只能看到事件、看不到来源 IP。历史数据不会回填。

**异常 IP 显示待确认，但我不想永久封**

不用处理，它只是候选；只有点「永久封禁」并确认后才会写入黑名单。已封可以在黑名单里解封。

**面板前面有 Nginx / Caddy**

可以让代理终止 TLS，但要在代理上把真实证书配好；面板指纹页会提示当前显示的不是客户端实际看到的证书。
